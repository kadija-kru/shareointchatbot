# Project Management Templates & Guidelines

**Contoso Corporation | Project Management Office (PMO)**  
**Version 1.4 | Updated February 2024**

---

## Overview

This document provides standard project templates and guidelines used by all project teams at Contoso Corporation. Using these templates ensures consistency, quality, and alignment with our PMO governance framework.

All templates are available to download from the PMO SharePoint site: `/sites/pmo/templates`.

---

## 1. Project Initiation

### 1.1 Project Charter Template

**Purpose**: Formally authorises the existence of a project and provides the project manager with authority to apply resources.

**Required Sections**:
- Project Title and ID
- Business Justification / Problem Statement
- Objectives and Success Criteria
- Scope (In-scope / Out-of-scope)
- Key Stakeholders and Roles
- High-Level Timeline and Budget
- Assumptions, Constraints, Dependencies
- Approval Signatures (Sponsor, PMO Lead)

**Instructions**: Fill in the Project Charter template within 5 business days of project approval. Submit to the PMO for registration and assignment of a Project ID.

### 1.2 Stakeholder Register Template

Document all stakeholders with:
- Name and Role
- Interest and Influence (High/Medium/Low)
- Preferred communication channel
- Engagement strategy (Inform / Consult / Collaborate / Empower)

## 2. Project Planning

### 2.1 Work Breakdown Structure (WBS)
The WBS decomposes the project scope into manageable components. Each work package should be:
- Completable in no more than 10 business days
- Owned by a single team member
- Linked to a deliverable or milestone

### 2.2 Project Schedule
Use the standard Gantt Chart template (Excel or MS Project).  
Required columns:
- Task ID, Task Name, Owner
- Start Date, End Date, Duration (days)
- Dependencies, Status (Not Started / In Progress / Complete / Blocked)
- % Complete, Comments

### 2.3 Risk Register Template

| ID | Risk Description | Likelihood (1-5) | Impact (1-5) | Score | Owner | Mitigation | Contingency | Status |
|---|---|---|---|---|---|---|---|---|
| R-001 | Example risk | 3 | 4 | 12 | PM | Action | Fallback | Open |

Score = Likelihood × Impact. Risks scoring ≥12 must be escalated to the project sponsor.

### 2.4 RAID Log
Maintain a RAID (Risks, Assumptions, Issues, Dependencies) log throughout the project. Review at every steering committee meeting.

### 3.2 Change Request Process
All scope, schedule, or budget changes must go through the formal Change Request (CR) process:
1. Raise a CR using the Change Request Form.
2. PM assesses impact on scope, schedule, budget, and risks.
3. CR reviewed at the next Steering Committee (or emergency review if urgent).
4. Decision recorded: Approved / Rejected / Deferred.
5. Project baseline updated if approved.

## 4. Project Closure

### 4.1 Project Closure Report Template

**Required Sections**:
- Project Summary (objectives vs outcomes)
- Schedule Performance (planned vs actual)
- Budget Performance (planned vs actual)
- Quality Summary (deliverables accepted vs rejected)
- Lessons Learned (what went well / what to improve)
- Recommendations for future projects
- Sign-off by Sponsor and PMO Lead

### 4.2 Lessons Learned Workshop
Conduct a retrospective within 2 weeks of project closure. Capture lessons in the central Lessons Learned library on the PMO SharePoint site.

## 5. PMO Governance

### 5.1 Project Classification

| Category | Budget Threshold | PMO Oversight Level |
|---|---|---|
| Small | < £50k | Light touch (monthly check-in) |
| Medium | £50k – £500k | Standard (steering committee) |
| Large | > £500k | Full governance (executive sponsor) |

### 5.2 Gate Reviews
Projects above £50k must pass formal Gate Reviews at:
- Gate 1: Concept approval
- Gate 2: Business case approval
- Gate 3: Design / solution approval
- Gate 4: Go-live / launch approval
- Gate 5: Post-implementation review
